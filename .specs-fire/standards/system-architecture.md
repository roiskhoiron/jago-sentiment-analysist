# System Architecture

## Overview

A modular sentiment analysis pipeline for Indonesian mobile-banking reviews, from scraping to reproducible inference.

## System Context

The system collects Google Play reviews, preprocesses Indonesian text, runs multiple experiments, and serves categorical sentiment inference.

### Context Diagram

```
Google Play Reviews -> Scraper -> Raw Dataset -> Preprocessing -> Features/Embeddings -> Models -> Evaluation -> Inference Output
```

### Users

- **Project Maintainer**: runs notebooks, validates metrics, and manages artifacts
- **Evaluator/Lecturer**: reviews reproducibility, constraints, and experiment quality

### External Systems

- **Google Play Store**: source of real user reviews
- **Google Colab**: optional execution environment

## Architecture Pattern

**Pattern**: Pipeline architecture
**Rationale**: Clear stage boundaries with reproducible artifacts between stages.

## Component Architecture

### Components

#### Scraping Module

- **Purpose**: Collect Indonesian user reviews
- **Responsibilities**: fetch reviews, normalize schema, save raw CSV/JSON
- **Dependencies**: Python scraper libraries, pandas

#### Preprocessing Module

- **Purpose**: Clean and standardize text
- **Responsibilities**: case folding, URL/emoji removal, tokenization, stopword removal
- **Dependencies**: regex, nltk/sastrawi, pandas

#### Training Module

- **Purpose**: Run ML/DL experiments
- **Responsibilities**: TF-IDF+LR, TF-IDF+SVM, IndoBERT fine-tuning
- **Dependencies**: scikit-learn, transformers, torch

#### Evaluation Module

- **Purpose**: Report model quality
- **Responsibilities**: accuracy, precision, recall, F1, confusion matrix
- **Dependencies**: sklearn.metrics, seaborn/matplotlib

#### Inference Module

- **Purpose**: Predict sentiment labels on new input
- **Responsibilities**: load artifacts, preprocess input, return categorical label
- **Dependencies**: saved model/tokenizer/vectorizer artifacts

### Component Diagram

```
[Scraping] -> [Preprocessing] -> [Training] -> [Evaluation]
                                 -> [Inference]
```

## Data Flow

Raw scraped reviews are stored first, then transformed into cleaned text features for experiment training; best-performing model and preprocessing artifacts are persisted and reused by inference.

```
raw_dataset.csv -> cleaned_dataset.csv -> train/test split -> model artifacts -> inference.py
```

## Technology Stack

| Layer | Technology | Purpose |
| Data Collection | Python scraping libs | collect real reviews |
| Processing | pandas + regex + NLP libs | cleaning and transformation |
| Classical ML | scikit-learn | TF-IDF baselines |
| Deep Learning | transformers + torch | IndoBERT fine-tuning |
| Reporting | sklearn metrics + seaborn | evaluation outputs |

## Non-Functional Requirements

### Performance

- **Dataset size**: >=10000 rows supported
- **Reproducibility**: deterministic runs with fixed seed

### Security

- No credential hardcoding
- No secret tokens in repository

### Scalability

Use modular notebook/script separation so each stage can scale independently.

## Constraints

- Must use self-scraped real data
- Must include >=3 sentiment classes
- Must run >=3 experiments
- Must not use ready-made labeled datasets

## Key Decisions

| Decision | Choice | Rationale |
| Data source | Google Play banking reviews | matches domain requirement |
| Experiment set | LR, SVM, IndoBERT | meets baseline + advanced comparison |
| Delivery format | notebooks + reproducible artifacts | aligns with Colab/Jupyter workflow |
